# 题目解析数据规范 v2（三段式 · 详版）

> 结构：**答案 → 一句话解法 → 解题步骤（三段式）→ 错因（只错项）→ 深度解析·考场策略（详细结构化）**。
> 本版两处调整（相对"终版"）：① 步骤恢复 `action / why / detail` 三段式；② 深度解析与考场策略合并为一块，但内容展开为结构化详版。
> 兼容：`solution` 与旧字段并存，有新字段优先，无则回退旧 Tab。
>
> **字数口径更新（2026-11-21）**：`why` 20~35 字、`detail` 40~55 字（下限为强制，教学解释与推理展开必须写透；**在区间内自然书写，不要顶格凑字**，避免每步都是同一长度）；错误类型 `type` 改为**开放填写、随机应变、随时拓展**——词表仅作参考建议，不再设硬闸门。
>
> **校验容差（2026-11-20 放宽，2026-11-21 随新口径调整）**：Python 校验器对字数边界**放行 ±5 字**——`why` 实际 15~40、`detail` 实际 35~60、`oneLiner` 至 40、`error.why` 至 35 均算通过。多写或少写 1~5 字不拦，避免卡边界；但仍应按目标区间（20~35 / 40~55）自然书写，不要故意贴着容差上限凑。

## 一、字段结构（5 个顶层字段）

```jsonc
"solution": {
  "answer": "A",                                      // ① 答案
  "oneLiner": "翻成 M→S→P 整体逆否得 ¬P→¬M，A 是此式",   // ② 一句话解法 ≤35字

  "steps": [                                           // ③ 解题步骤：三段式
    {
      "n": 1,
      "action": "逐句翻译成箭头",                        // 做什么（≤12字）
      "why": "条件句不翻译就无从推理，先要把关联词变成箭头，否则串链逆否都失去依据",  // 为什么这么做（20~35字，不能只写结果）
      "detail": "①只有S才M⇒M→S；②只要S就P⇒S→P；③想S必须Q⇒S→Q，三条首句逐一翻完即成链",  // 具体内容（40~55字）
      "key": true                                       // 可选：关键步高亮
    }
  ],

  "errors": [                                          // ④ 只写错项
    { "o": "B", "type": "肯后推肯前", "why": "题干 M→S，B 写成 S→M" }
  ],

  "insight": {                                         // ⑤ 深度解析 + 考场策略（合并、详细）
    "position": "判断推理 → 逻辑判断 → 翻译推理 → 逆否等价",
    "signal": "题干出现只有…才/只要…就/必须/要想…就 → 先全翻箭头、串链、再逆否",
    "essence": "条件句只有两种有效推理：肯前推肯后、否后推否前，其余方向无效",
    "formula": [
      "只有A才B ⇒ B→A（后推前）",
      "只要A就B ⇒ A→B（前推后）",
      "串链 X→…→Y ⇒ 逆否 ¬Y→¬X"
    ],
    "pitfalls": [
      "必要（只有…才）后推前，充分（只要/如果）前推后，别混",
      "「关键在于/核心是」不是逻辑关联词，不能翻成条件"
    ],
    "strategy": {
      "shouldDo": "必做",
      "bestWay": "先把四个关联词全翻成箭头再比对选项，比逐项回读题干快一倍",
      "timeCost": "约60秒",
      "traps": "「关键在于」看着像条件词，误翻成就误选C"
    }
  }
}
```

## 二、相对上一版的变化

| 项目 | 上一版（终版） | 本版 |
|------|--------------|------|
| 步骤 | 每步一句话 `{n,text,key}` | **三段式** `{n,action,why,detail,key}` |
| 深度解析·策略 | 字符串数组，每条一句 | **结构化对象**：position/signal/essence/formula[]/pitfalls[]/strategy{}，内容展开 |
| why 字数 | ≤40 字（无下限） | **20~35 字**（下限强制，写透教学价值；校验放行 15~40） |
| detail 字数 | ≤80 字（无下限） | **40~55 字**（下限强制，写透推理；校验放行 35~60） |
| error.type | 固定词表硬校验 | **开放填写**（随机应变、随时拓展） |

顶层字段仍是 5 个，但步骤和解析块内部更详实。

## 三、各字段写法

**`steps[]` 三段式**
- `action`：这一步做什么，动词开头，≤12 字。
- `why`：**为什么这么做**（教学价值所在），**20~35 字**（下限强制），不能只写结果——要讲清"不改这一步会怎样、为什么这样想"。在区间内自然书写，不要每步都顶到 35 字。校验放行 15~40 字。
- `detail`：具体推理内容、公式、翻译结果，**40~55 字**（下限强制），要把推导过程写完整、可复现。在区间内自然书写，不要每步都顶到 55 字。校验放行 35~60 字。
- `key`：锁定答案那步标 `true`，UI 高亮；至多一个。
- 无分步推导题型（图形推理）写 `[]`，UI 显示"本题以图形辨识为主"。

**`errors[]`**——只列错项，正确项不写。`type` **开放填写**（见下方说明），`why` ≤30 字。

**错误类型（开放填写，随机应变）**：`type` 用来点出错项背后的思维错误，**不受固定词表约束，可随时拓展、按题量身造词**。下方仅为**参考建议**（非强制、非穷尽）：

- 逻辑类：`肯后推肯前`/`否前推否后`/`箭头方向颠倒`/`强加因果`/`因果倒置`/`另有他因`/`无中生有`
- 概念类：`偷换概念`/`以偏概全`/`样本不当`/`范围扩大`/`范围缩小`/`绝对化`/`无关选项`/`力度不足`/`支持项`
- 言语类：`搭配不当`/`语义重复`/`偏离主旨`/`衔接不当`/`语序不当`/`不合设问`
- 数量/资料类：`计算错误`/`公式误用`/`基期现期混淆`/`单位陷阱`/`比例用反`/`知识点错配`

> 遇到参考表没有的错因（如"折返相遇中把间距当全长""比重变化方向判反"），**直接按实际错因造词**，越具体越有教学价值。校验器只检查 `type` 非空，不再拦截表外类型。

**`insight` 详版**
- `position`：体系定位，知识树坐标路径。
- `signal`：识别信号，什么题干特征该调用什么方法——可迁移的核心。
- `essence`：本质，真正考的能力/规则。
- `formula[]`：通式模板，可套用的公式，每条一句。
- `pitfalls[]`：易混易错，典型撞坑。
- `strategy`：考场策略——`shouldDo`(取舍)/`bestWay`(最优解)/`timeCost`(耗时)/`traps`(陷阱)。
- 各子字段可缺省（有则写精，无则略），禁止"本题考查XX，要注意XX"这类空话。

> 上面是**字段清单**。四个核心字段（信号/本质/通式/最优解）的**详细编写规则 + 复盘价值**见下方专节——这是把它们从"写了一行"升级到"写出可迁移价值"的操作手册。

## 三·补、insight 四字段详细编写规则（信号 · 本质 · 通式 · 最优解 · 复盘导向）

### 总纲：四字段是一条认知链，也是一份结构化复盘

`answer/steps/errors` 记录的是**这道题发生了什么**（一次性事实）；`insight` 四字段提炼的是**这一类题下次怎么做**（可迁移能力）。写解析 = 做一次复盘，四字段就是把复盘结论固化下来的四个格子——缺一格，这道题的收益就漏一块。

| 字段 | 认知层 | 回答的问题 | 复盘动作 | 沉淀形态 |
|---|---|---|---|---|
| `signal` 信号 | 识别 | 看到什么认出它 | 遮住解析看题干，能否想起方法 | 检索钩子 |
| `essence` 本质 | 理解 | 换个马甲还在考什么 | 剥壳，把它和同类题连成网 | 底层原理 |
| `formula[]` 通式 | 迁移 | 能不能直接套 | 与技法库/速查表对照、回写 | 可携带工具 |
| `strategy.bestWay` 最优解 | 效率 | 怎么最快又不错 | 追问更快的路，重做改进 | 实战打法 |

一句话记忆：**信号认得出 → 本质看得透 → 通式套得上 → 最优解做得快。**

**写四字段的时序纪律（2026-11-20 强化）**：四字段必须在**独立解阶段就先填出一版**，再看技法库逐字段比对——不是"看完库再写"。原因有二：① 看完库再写，容易把库里的 signal/formula 直接抄成答案，失去独立判断，也发现不了库的盲点（第65题独立解才揪出选言题"主体前提"维，库卡片只讲否一推一分不清 A/D）；② 先有自己的一版，比对才能"逐字段"落到具体差异上（库的 bestWay 更快？还是我的 formula 更细？），差异择优、更细则回补。这一步与项目「先独立解，再比对库」闭环是同一条纪律——四字段不例外。

### 1. `signal` 信号 —— 识别层（认得出）

**定位**：题干「可观察特征 → 该调用的方法」的映射，是整道题的**检索入口**，解决"拿到题不知道用哪招"。

**编写规则**
- 句式：`看到【特征词/结构/数字特征/问法】→ 用【方法】`。
- **多特征叠加用 `+` 连接（2026-11-21 新增）**：当识别需要多个特征同时成立时，写成 `【特征A】+【特征B】+【特征C】→ 用【方法】`，用 `+` 并列条件、`→` 指向结论，一眼看清"哪几个条件共同触发"。
  - 示例：`封闭外框 + 内叠线条 + 逐图渐变 → 走局部数量`（第53题）
  - 示例：`出现"只有…才" + 关联词串链 + 问"可以推出" → 全翻箭头再逆否`
  - 单特征时不必硬凑 `+`，一个 `看到…→用…` 即可。
- 特征必须**肉眼可扫**：关联词、数字特征、元素关系、问法关键词、量纲；禁止"这题较难需分析"这类不可观察的描述。
- 能写"排除性信号"更好——既说激活什么，也说排除什么（如"元素完全相同只位置变 → 平移，排除数量/样式"）。
- **换壳测试**：把人名、场景、具体数字换掉，这条信号还成立吗？成立才是好信号。
- 数量/资料的信号带上**精度线索**（差距大→粗估、差距小→精算；至少/保证→最不利）。

| 好信号 ✅ | 坏信号 ❌ |
|---|---|
| 各图元素完全相同只是位置变 → 平移，排除数量/样式 | 本题考查图形推理，需要仔细分析 |
| 出现"只有…才/只要…就/必须"→ 全翻箭头串链再逆否 | 这是一道翻译推理题 |
| 论据与论点主词不同 → 优先找搭桥项 | 考查逻辑判断能力 |

**对复盘的帮助**：复盘时**遮住答案只看题干**，看 signal 能否立刻触发方法。想不起 = 信号没写到位 = 下次还会卡在同一处。信号是把"这一道题"变成"这一类题"的第一道闸门。

**自检**：换掉故事和数字后还成立吗？看到它，方法灯会亮吗？

### 2. `essence` 本质 —— 理解层（看得透）

**定位**：剥掉情境外壳后真正考查的**底层原理/规则/能力**，回答"这道题换个马甲还是在考什么"。

**编写规则**
- 句式：`本质是【原理】；考的是【能力】`。
- 抽象到**原理级**，不是解法级——解法是"怎么做"，本质是"为什么这样做才成立"。
- **剥壳测试**：去掉专业术语、具体数字、人物场景，剩下的话还能指导一类题吗？
- **只抓一个点**：本质通常一句话，不要罗列多个（那是 `formula`/`pitfalls` 的活）。
- 与 `position` 呼应：本质要能解释"为什么归到这个节点"。

| 好本质 ✅ | 坏本质 ❌ |
|---|---|
| 条件句只有两种有效推理：肯前推肯后、否后推否前，其余方向无效 | 本题考查逆否等价，要注意箭头方向 |
| 加强的本质是让论点更可信，最直接是补上论据通往论点的那一步 | 考查论证加强 |
| 弹力依赖接触，接触消失即刻为零——考判据，不是算数值 | 本题考查弹力计算 |

**对复盘的帮助**：本质决定**迁移半径**。只记解法，迁移半径 = 1 道题；抽出本质，迁移半径 = 一类题甚至跨题型。复盘时追问"这题和上周那题是不是同一个本质？"，就能把散题连成体系记忆。

**自检**：去掉数字场景后还成立吗？能解释 `position` 吗？是不是只有一句？

---

### 3. `formula[]` 通式 —— 迁移层（套得上）

**定位**：把本质固化成**可直接套用的公式/模板/判别条件**，是四字段里唯一能"直接带走"的东西。

**编写规则**
- 每条一句，带**变量名**（A/B/X→Y）而非具体数字，独立可用（单拎任一条就能指导一次判断）。
- 两类写法，**都不许空**：
  - 有公式的题 → 符号化通式：`只有A才B ⇒ B→A`、`首超 n=(目标−现期)/增量 向上取整`。
  - 无公式的题（言语/图推/科推）→ 判别条件或排序：`加强力度：搭桥＞补充论据＞举例`、`平移三要素=谁在动+往哪动+动几格`。
- 符号说人话：`甲＋乙＝100` 不写 `甲乙＝100`。
- 数量关系的通式须与《数量关系-情况解法速查.md》对应模块一致；发现更快式**同时回写两处**并标实测日期。

| 好通式 ✅ | 坏通式 ❌ |
|---|---|
| 串链 X→…→Y ⇒ 整体逆否 ¬Y→¬X | 要注意计算准确 |
| 完全失重：只受重力 ⇒ 合外力=mg，对下方无压力 | 本题答案是A |
| 搭桥式 = 在 A(论据关键词) 与 B(论点关键词) 间建立 A→B | 加强题要找支持项 |

**对复盘的帮助**：复盘时把本题通式和技法库/速查表对照——库里已有 = 强化记忆；库里没有 = 一个**沉淀点**，回写资产（沉淀闭环）。积累下来，`formula[]` 就是你自己的"考场速查手册"。

**自检**：每条带变量吗？单拎出来能用吗？数量题和速查表一致吗？是数组不是字符串吗？

### 4. `strategy.bestWay` 最优解 —— 效率层（做得快）

**定位**：在"能做对"之上，给出考场上**最快最稳**的那条路，回答"怎么做得又快又不错"。与 `steps`（可复算的常规解法）可以不同——`steps` 保"算得对"，`bestWay` 追"考场快"。

**编写规则**
- 句式：`先【关键动作】，一步定【什么】，比【常规做法】快【多少/为什么】`。
- 必须点明**快在哪**：省掉了什么步骤（不四选项全算）、找到同源项（①③同源省一半推理）、还是换了切入点（先写论据→论点再看选项）。
- **动词开头、能照着做**；禁止"要灵活处理""认真读题仔细算"。
- 与选项精度联动：数量/资料的最优解通常含"看差距定精度"（粗估 1 个 / 精算 2 个 / 禁四选项全算）。
- 若本题打出了更快打法 → 写进 `bestWay` 的同时触发**沉淀闭环**（回写技法库 + 速查表 + 同步技能）。

| 好最优解 ✅ | 坏最优解 ❌ |
|---|---|
| 四个关联词一次性全翻箭头，再拿选项逐一比对，比逐项回读题干快一倍 | 认真分析即可选出 |
| 挑含稀缺项(孙)的选项做反证，一两步就出矛盾，不必四选项全推 | 用代入法 |
| 先写下"论据词→论点词"，看哪个选项正好连上这两词，几秒可定 | 用排除法 |

**对复盘的帮助**：复盘分"做对"和"做快"两层——前三字段解决做对，`bestWay` 专治"会做但超时"。复盘时追问"这次用了多久？重做一遍我会怎么更快？"，把"这次的笨办法"升级成"下次的最优解"。它是**沉淀闭环的入口**，让个人复盘和团队资产形成正循环。

**自检**：动词开头吗？说清快在哪吗？和 `steps` 有区分度吗？

---

### 五步复盘法：把四字段真正用起来

做完题（或回看旧题）后，按此顺序自问，每问对应一个字段：

1. **认**：遮住解析看题干 → 只看 `signal`，能否立刻想起方法？（识别断点）
2. **断**：对了还是错了、快了还是慢了？定位到 `errors` 与 `strategy.timeCost`。（断点定位）
3. **透**：剥壳看 `essence`，这题和哪几题是同一个本质？（建立体系）
4. **带**：抄走 `formula[]`，这条能不能进我的速查手册？库里没有就回写。（沉淀工具）
5. **快**：追问更快的路，重做一遍怎么改？写进 `bestWay` 并回写资产。（提速闭环）

> 五步走完，一道题才从"一次性经验"变成"可迁移能力"。**复盘不是再看一遍答案，而是把这道题的收益榨成 signal/essence/formula/bestWay 四份可复用的资产。**

## 四、渲染约定

- 五块顺序：答案解法（高亮）→ 解题步骤（三段式，action 为主、why 为副、detail 可展开）→ 错因 → 深度解析·考场策略（分组展示）。
- 题干与选项原文在弹窗左栏已有，右栏不重复。
- 无 `solution` 时回退旧字段（旧 Tab 渲染）。

## 五、校验要点

- `answer` 与 `ans` 一致；`oneLiner` ≤35 字
- `steps[].n` 连续；`action` ≤12 字、**`why` 20~35 字**、**`detail` 40~55 字**（校验边界均放行 ±5 字）；至多一个 `key`
- `errors` 字母集合 = 选项字母 − 答案字母（只错项）
- 每个 error 的 `type` **仅需非空**（开放填写，不查词表）、`why` ≤30 字
- `insight` 为对象，含 `strategy` 子对象；各子字段长度适度
