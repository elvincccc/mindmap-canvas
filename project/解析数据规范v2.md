# 题目解析数据规范 v2（三段式 · 详版）

> 结构：**答案 → 一句话解法 → 解题步骤（三段式）→ 错因（只错项）→ 深度解析·考场策略（详细结构化）**。
> 本版两处调整（相对"终版"）：① 步骤恢复 `action / why / detail` 三段式；② 深度解析与考场策略合并为一块，但内容展开为结构化详版。
> 兼容：`solution` 与旧字段并存，有新字段优先，无则回退旧 Tab。
>
> **字数口径更新（2026-11-19）**：`why` 20~45 字、`detail` 50~70 字（下限为强制，教学解释与推理展开必须写透；**在区间内自然书写，不要顶格凑字**，避免每步都是同一长度）；错误类型 `type` 改为**开放填写、随机应变、随时拓展**——词表仅作参考建议，不再设硬闸门。
>
> **校验容差**：Python 校验器对字数边界**放行 ±3 字**——`why` 实际 17~48、`detail` 实际 47~73、`oneLiner` 至 38、`error.why` 至 33 均算通过。多写或少写 1~3 字不拦，避免卡边界；但仍应按目标区间（20~45 / 50~70）自然书写，不要故意贴着容差上限凑。

## 一、字段结构（5 个顶层字段）

```jsonc
"solution": {
  "answer": "A",                                      // ① 答案
  "oneLiner": "翻成 M→S→P 整体逆否得 ¬P→¬M，A 是此式",   // ② 一句话解法 ≤35字

  "steps": [                                           // ③ 解题步骤：三段式
    {
      "n": 1,
      "action": "逐句翻译成箭头",                        // 做什么（≤12字）
      "why": "条件句不翻译就无从推理，必须先把关联词变成箭头，否则后面串链和逆否都失去依据",  // 为什么这么做（20~45字，不能只写结果）
      "detail": "①只有S才M ⇒ M→S；②只要S就P ⇒ S→P；③想S就必须Q ⇒ S→Q，三条首句逐一翻完即成链",  // 具体内容（50~70字）
      "key": true                                       // 可选：关键步高亮
    }
  ],

  "errors": [                                          // ④ 只写错项
    { "o": "B", "type": "肯后推肯前", "why": "题干 M→S，B 写成 S→M" }
  ],

  "insight": {                                         // ⑤ 深度解析 + 考场策略（合并、详细）
    "position": "判断推理 → 逻辑判断 → 翻译推理 → 逆否等价",
    "signal": "题干出现只有…才/只要…就/必须/要想…就 → 先全翻箭头、串链、再逆否",
    "essence": "条件句只有两种有效推理：肯前推肯后、否后推否前，其余方向无效",
    "formula": [
      "只有A才B ⇒ B→A（后推前）",
      "只要A就B ⇒ A→B（前推后）",
      "串链 X→…→Y ⇒ 逆否 ¬Y→¬X"
    ],
    "pitfalls": [
      "必要（只有…才）后推前，充分（只要/如果）前推后，别混",
      "「关键在于/核心是」不是逻辑关联词，不能翻成条件"
    ],
    "strategy": {
      "shouldDo": "必做",
      "bestWay": "先把四个关联词全翻成箭头再比对选项，比逐项回读题干快一倍",
      "timeCost": "约60秒",
      "traps": "「关键在于」看着像条件词，误翻成就误选C"
    }
  }
}
```

## 二、相对上一版的变化

| 项目 | 上一版（终版） | 本版 |
|------|--------------|------|
| 步骤 | 每步一句话 `{n,text,key}` | **三段式** `{n,action,why,detail,key}` |
| 深度解析·策略 | 字符串数组，每条一句 | **结构化对象**：position/signal/essence/formula[]/pitfalls[]/strategy{}，内容展开 |
| why 字数 | ≤40 字（无下限） | **20~45 字**（下限强制，写透教学价值；校验放行 17~48） |
| detail 字数 | ≤80 字（无下限） | **50~70 字**（下限强制，写透推理；校验放行 47~73） |
| error.type | 固定词表硬校验 | **开放填写**（随机应变、随时拓展） |

顶层字段仍是 5 个，但步骤和解析块内部更详实。

## 三、各字段写法

**`steps[]` 三段式**
- `action`：这一步做什么，动词开头，≤12 字。
- `why`：**为什么这么做**（教学价值所在），**20~45 字**（下限强制），不能只写结果——要讲清"不改这一步会怎样、为什么这样想"。在区间内自然书写，不要每步都顶到 45 字。校验放行 17~48 字。
- `detail`：具体推理内容、公式、翻译结果，**50~70 字**（下限强制），要把推导过程写完整、可复现。在区间内自然书写，不要每步都顶到 70 字。校验放行 47~73 字。
- `key`：锁定答案那步标 `true`，UI 高亮；至多一个。
- 无分步推导题型（图形推理）写 `[]`，UI 显示"本题以图形辨识为主"。

**`errors[]`**——只列错项，正确项不写。`type` **开放填写**（见下方说明），`why` ≤30 字。

**错误类型（开放填写，随机应变）**：`type` 用来点出错项背后的思维错误，**不受固定词表约束，可随时拓展、按题量身造词**。下方仅为**参考建议**（非强制、非穷尽）：

- 逻辑类：`肯后推肯前`/`否前推否后`/`箭头方向颠倒`/`强加因果`/`因果倒置`/`另有他因`/`无中生有`
- 概念类：`偷换概念`/`以偏概全`/`样本不当`/`范围扩大`/`范围缩小`/`绝对化`/`无关选项`/`力度不足`/`支持项`
- 言语类：`搭配不当`/`语义重复`/`偏离主旨`/`衔接不当`/`语序不当`/`不合设问`
- 数量/资料类：`计算错误`/`公式误用`/`基期现期混淆`/`单位陷阱`/`比例用反`/`知识点错配`

> 遇到参考表没有的错因（如"折返相遇中把间距当全长""比重变化方向判反"），**直接按实际错因造词**，越具体越有教学价值。校验器只检查 `type` 非空，不再拦截表外类型。

**`insight` 详版**
- `position`：体系定位，知识树坐标路径。
- `signal`：识别信号，什么题干特征该调用什么方法——可迁移的核心。
- `essence`：本质，真正考的能力/规则。
- `formula[]`：通式模板，可套用的公式，每条一句。
- `pitfalls[]`：易混易错，典型撞坑。
- `strategy`：考场策略——`shouldDo`(取舍)/`bestWay`(最优解)/`timeCost`(耗时)/`traps`(陷阱)。
- 各子字段可缺省（有则写精，无则略），禁止"本题考查XX，要注意XX"这类空话。

---

## 四、渲染约定

- 五块顺序：答案解法（高亮）→ 解题步骤（三段式，action 为主、why 为副、detail 可展开）→ 错因 → 深度解析·考场策略（分组展示）。
- 题干与选项原文在弹窗左栏已有，右栏不重复。
- 无 `solution` 时回退旧字段（旧 Tab 渲染）。

---

## 五、校验要点

- `answer` 与 `ans` 一致；`oneLiner` ≤35 字
- `steps[].n` 连续；`action` ≤12 字、**`why` 20~45 字**、**`detail` 50~70 字**（校验边界均放行 ±3 字）；至多一个 `key`
- `errors` 字母集合 = 选项字母 − 答案字母（只错项）
- 每个 error 的 `type` **仅需非空**（开放填写，不查词表）、`why` ≤30 字
- `insight` 为对象，含 `strategy` 子对象；各子字段长度适度
