# 行测五合一看图 · 项目工作指令

## 目标
持续向思维导图画布填充有价值的题目与解析，小步迭代成更好的版本。
「有价值」判据：考场方法能讲透 + 有技法沉淀价值 + 答案可核准；拿不准的先问用户，别自行拍板。

## 现状锚点（每次开工运行时读取，不写死——易变事实）
> 以下数字随迭代变化，**禁止凭记忆或写死的旧值**，按需用命令现取（与 manifest 第八章一致）：
- 解析覆盖数：`grep -rho '"solution"' mindmap-demo/data/subjects/p*.json | wc -l`（最近实测 204）
- 线上 commit：`gh api repos/elvincccc/mindmap-canvas/commits/main --jq '.sha[0:7]'`（最近实测 a2e66ba）
- 配图数：`find mindmap-demo/assets/img -type f | wc -l`（最近实测 52）
- 常识判断按用户决定暂缓；线上地址 https://elvincccc.github.io/mindmap-canvas/。图片全部走仓库 `assets/img/` 同域相对路径，OSS 已因欠费废弃、禁外链。

## 解题与改写闭环（强制）
1. **先独立解（含 insight 四字段），再比对库，择优选法**（2026-11-20 升级，替掉"解析前先读库"；同日再强化"四字段也纳入独立解"）：① 拿到题先自己定性、按考场解法独立推一遍，**不看技法库**——不仅解出答案/步骤，还要**同时独立填出 insight 四字段**（signal 什么信号触发、essence 考什么本质、formula 可套通式、bestWay 最快判法），先形成一版"纯自己"的五块+四字段；② 解完再翻《分科技法库.md》对应科目条目，**逐字段比对**（尤其 signal/formula/bestWay）：库里更快/更稳的用库，自己更细的（如第65题独立解补出选言题"主体前提"维、库卡片只讲否一推一分不清A/D）用自己并回补；③ 差异择优：库更优则用库，自己更细则用自己并回补。**独立解四字段的价值**：避免"看完库再写四字段"变成抄库式空话，让盲点/差异落在具体字段上。**但独立解不许走硬算笨路**（第77题比重硬算、第83题逐年累加、第87题逐项除比值仍是教训）——这是"解完必须比对库"这道关要兜的。
2. 比对发现库里没有的更好方法/更细判据（如第65题独立解揪出选言题的"主体前提"维，库卡片只讲否一推一、分不清A与D），写进解析的同时**回补技法库对应小节**并标实测日期——让库越用越厚。**回补后同步到自建技能**：`cd ~/.codebuddy/skills/xingce-coach && python3 scripts/sync_assets.py`（技能内资产是项目快照；`--check` 查一致性，解题前自检）。
3. 挂节点前先过「归类三问法」：①题干问的是什么量（增量/增速/比重/平均数/综合判断）②用什么公式（对照节点名）③解析 `insight.position` 坐标是否与挂载一致。凡锁定单一考点的题一律归对应知识点节点，只有「四项各考一点、须逐项验证」的综合题才进「能够推出判断」——它不是收纳未知考点的垃圾桶。挂错用 `tools/regroup_examples.py --dry` 预演后迁移。
4. 题型判断、重写范围、执行做法有歧义 → 先问用户再动手。

## token 经济（贯穿全程）
