# 试卷错题录入工作流程（PDF → 提取 → 解析 → 入库 → 部署）

> 适用范围：把一份带「正确答案 / 你的答案」的粉笔版行测真题 PDF，转成画布上可查看 v2 朱批解析的错题节点。
> 本文所有命令均在 `/workspace/mindmap-server` 目录下执行（除特别说明），且基于对该目录工具的**实际阅读**与对真实试卷 PDF 的实测。

---

## 一、总览

**一句话**：把「人工逐题填表」改造成「上传 PDF → 报题号（或自动识别错题）→ AI 生成结构化解析 → 脚本校验 → 入库拆包 → 一次原子部署 → 线上自动验证」的标准流水线，人只做低认知负担的选题号/复核，AI 与脚本做解题、结构化和发布。

> **⭐ 推荐主路径：`ingest_v2.py` 一键流水线**。下文 Step 1~9 是「原理拆解版」，讲每一步在做什么；实际录入直接用「零、v2 一键流水线」的三条命令即可，脚本已把 hit 派生、样板防冲、校验、拆包、部署全部自动化。老脚本 `ingest.py`（写后端 DB）保留作兼容，但**不走它录入 v2 题**。

```
   试卷PDF
     │  ① 上传到 /root/uploads/
     ▼
  识别对错题  ──  ingest_v2.py derive-answers：按顺序 zip 题号/正确/你的 → 自动算 hit
     │  ② answers.json（每题 correct/mine/hit，歧义告警）
     ▼
  按题号提取  ──  pdf_extract.py --nums：题干+选项+配图（材料表格需多模态读图）
     │  ③ AI 五块结构化（只写 solution，不写 ans/hit）
     ▼
  questions.json ── 含 vol/subject/node + 题目内容 + solution
     │  ④ ingest_v2.py ingest：ans/hit 自动派生 + 结构校验 + 幂等挂载
     ▼
  4处数据同步 ── 以 demo 为基准合并 → 覆盖 server/demo/js/pN → split_data.py
     │  ⑤ validate_v2 全 PASS + 数据对账（总数+各科分布）
     ▼
  原子部署 ──  gh_upload_atomic.py 一次 commit = 一次 Pages 部署（--deploy）
     │  ⑥ verify_deploy.py / verify_qNN.py 事件驱动验证
     ▼
  画布可见 ✅
```

## 零、v2 一键流水线（推荐主路径）

`ingest_v2.py` 是本次沉淀的核心产物，把原来分散、易错的手工步骤收敛成一条命令链。**两个防呆设计**：

- **hit 自动派生**：题目文件里**根本不写** `ans`/`hit`，脚本从 `answers.json`（由 PDF 解析）按题号取 `correct` 派生 `ans`、`set(correct)==set(mine)` 派生 `hit`。想手填都没有入口——从根上杜绝「第71题填反」。
- **样板防冲 + 幂等**：以 `mindmap-demo/data.json`（含全部 v2 样板）为合并基准，按 `src` 先删后加，重复跑 MD5 不变；覆盖 4 处后再 split，样板不会丢。

```bash
cd /workspace/mindmap-server
PDF='/root/uploads/xxx.pdf'

# ① 解析权威答案对（90题/30错/零歧义；粉笔PDF答案总表前置，脚本按顺序zip三序列）
python3 tools/ingest_v2.py derive-answers --pdf "$PDF" --out /tmp/answers.json

# ② AI 写 questions.json（只写 q/opts/img/solution，卷名/科目/节点在顶层；样例见脚本底部 EXAMPLE_QUESTIONS）
#    ⚠ 不要写 ans/hit——写了也会被派生值覆盖并校验，写错直接 FAIL

# ③ 预览（不写任何文件，先看派生结果对不对）
python3 tools/ingest_v2.py ingest --questions questions.json --answers /tmp/answers.json --dry-run

# ④ 正式入库（写4处 + split + 校验 + 对账；不带 --deploy 则不推线上）
python3 tools/ingest_v2.py ingest --questions questions.json --answers /tmp/answers.json

# ⑤ 确认无误后加 --deploy 原子部署（也可复用上面已写入的数据直接 gh_upload_atomic.py）
python3 tools/ingest_v2.py ingest --questions questions.json --answers /tmp/answers.json --deploy

# ⑥ 线上验证
python3 tools/verify_deploy.py --mode online
```

`questions.json` 顶层结构：

```json
{
  "vol": "2025广东省考真题",
  "subject": "资料分析",
  "node": "累计求当期：当期值=本期累计−上期累计",
  "questions": [
    {"num": 71, "q": "...", "opts": ["A.4.34", ...], "img": "assets/img/xxx.ext 或留空",
     "solve": "旧字段(可选)", "analysis": "旧字段(可选)",
     "steps": [], "exclude": [], "solution": {"answer":"A", "oneLiner":"...", "steps":[...], "errors":[...], "insight":{...}}}
  ]
}
```

> **实测记录（2026-11-18）**：用本试卷 + 第71题跑通——`derive-answers` 解析 90 题/30 错/零歧义（第49题做对、第53/71题做错，与 PDF 逐题吻合）；`ingest --dry-run` 在不提供 ans/hit 的情况下正确派生 `ans=A/hit=做错`；故意把 `solution.answer` 写成 B 时脚本 FAIL 并中止、零文件写入；连续跑两次 `data.json` 的 MD5 完全一致（幂等）。

## 四、分步操作

### Step 1　上传试卷 PDF 到沙箱

用户把 PDF 放进 `/root/uploads/`（会话上传目录每次可能不同，以实际回显路径为准）。确认文件：

```bash
ls -lh "$PDF"
# -rw-r--r-- 1 root root 1.1M ... 2025年广东省公务员录用考试《行测》题（网友回忆版）.pdf
```

**产物**：沙箱中一份可读取的 PDF。先确认是不是文本型：`pdftotext "$PDF" - | head` 能出中文即文本型；输出乱码/`\x00` 则需 OCR（用 `pdf-image-text-extractor` 技能）。

---

### Step 2　识别对错题（对比「正确答案 / 你的答案」）

**实测事实**（本次试卷）：25 页、90 题（题号 1~90），答案对以 `正确答案：X` / `你的答案：Y` 行形式嵌在正文里，**并不稳定落在 `pdf_extract.py` 的每题块内**（实测 90 题仅 23 题的 `raw` 同时含两个标记）。因此这一步用**全文正则配对**，不要依赖提取器的分块。

```bash
python3 - <<'PY'
import fitz, re
pdf='/root/uploads/wb-agentserver-5cf14749-26b5-421b-9f85-254bd79350bb-uploads-1795006/2025年广东省公务员录用考试《行测》题（网友回忆版）.pdf'
d=fitz.open(pdf); txt='\n'.join(p.get_text('text') for p in d)
pat=re.compile(r'正确答案：\s*([A-D]+)[^\n]*\n\s*你的答案：\s*([A-D]+)')
pairs=pat.findall(txt)
wrong=[(i+1,c.strip(),y.strip()) for i,(c,y) in enumerate(pairs) if c.strip()!=y.strip()]
print(f'配到答案对 {len(pairs)} 组；按顺序映射题号时发现 {len(wrong)} 处不一致')
print('错题号(按顺序映射):', [w[0] for w in wrong])
PY
```

本次实测输出：`配对数 86；不一致 30 处`，题号形如 `6, 9, 11, 14, 15, 17, 18, 26, 29, 34, 36, 37, 39, 41, 42, 45, 50, 52, 57, 58, 60, 63, 67, 70, 71, 73, 80, 81, 85, 86`。

> **必须人工核对**：用户说「31 道做错」，正则得到 30，差 1 题——4 组答案对因跨页换行/多选格式没被正则捕获，且「按出现顺序映射题号」在判断题（1~4 题）区域可能错位。请把正则结果和用户给出的错题清单交叉比对，**以人工确认的题号为准**。这是目前唯一无法完全自动化的环节。

**产物**：确认后的错题号清单（下一步 `--nums` 的输入）。

---

### Step 3　按题号提取题干 + 选项 + 配图（`pdf_extract.py`）

先看 PDF 里检测到哪些题号，再提取指定题号；有图形题时同时把内嵌图片导出来。

```bash
# 3.1 列出全部题号（确认题号体系与页号）
python3 tools/pdf_extract.py "$PDF" --dump-all | head -20

# 3.2 提取确认后的错题 → extracted.json
python3 tools/pdf_extract.py "$PDF" \
  --nums 6,9,11,14,15,17,18,26,29,34,36,37,39,41,42 \
  --out extracted.json --imgdir ./pages_img
```

输出示例（`extracted.json`，实际 JSON 结构来自源码 `extract()`）：

```json
{
  "6": {
    "num": 6, "page": 2,
    "q": "（判断题）……",
    "opts": ["A. 正确", "B. 错误"],
    "raw": "6.\n（判断题）……\n"
  }
}
```

`--imgdir` 会把 PDF 内嵌图片写成 `pages_img/p{页}_x{xref}.{ext}`（脚本本身**不把图片路径写进 JSON**，需人工把图与题号对应，见决策点 3）。

**能力/边界**（读源码所得）：
- 题号识别模式：`^\s*第N题`、`^\s*N[.．、]`、`^\s*[（(]N[）)]`，仅接受 1~300；
- 选项支持「分行」与「行内 A. B. C. D.」两种排版，用 `([A-D])\s*[.．、:：]\s*` 拆分；
- `raw` 字段**截断到前 2000 字符**，答案标记可能落在截断之外（这正是 Step 2 单独做的原因）。

**产物**：`extracted.json`（题干/选项/页号/原文）、`pages_img/`（内嵌图片）。

**从 PDF 精准裁图（图源可靠时优先用此法）**：题图归属绝不能按题号或导出顺序猜——多试卷同题号会撞车、同页多图会错位。可靠流程：
1. 网盘附件：`tdrive.file_download(file_id)` 取临时签名 URL（`curl -sSL -o 本地 "URL"` 原样下载，勿解析 URL）；本地上传：`/root/uploads/`。
2. `pdftotext -layout` 按 `\f` 分页，正则定位"第N题 + 题干关键词"所在页。
3. PyMuPDF：`page.get_images(full=True)` 列图，`doc.extract_image(xref)` 导出，排除页眉 xref 与小图。
4. **判归属看坐标**：`page.get_image_rects(xref)` 拿图片 y 坐标，与题干文字 y 坐标比对——图通常在题干下方；同一 xref 可能被相邻两题共享，务必对位（2026 第50题曾因此把第49题图当成自己的）。
5. 生成联系表视觉复核 → 转目标格式（保持文件名以便数据 URL 不变）→ 覆盖 `assets/img/` → 原子部署 → 线上核对新图 MD5。

### Step 4　AI 生成 v2 结构化解析（五块结构）

把 `extracted.json` 中每题的 `q / opts` 连同 Step 2 确认的答案，交给 AI 按 `解析数据规范v2.md` 生成 `solution` 五块结构，汇总成 `questions.json`。

**Prompt 模板**（可直接复制）：

```
你是行测真题解析专家。下面给出一道题的题干、选项、正确答案，以及它的答案对形式。
请严格按照「解析数据规范v2（三段式·详版）」输出该题的 solution 对象，只输出 JSON，不要解释。

【v2 五块结构要求】
1) answer：必须与给定正确答案一致（单选题一个字母，多选题字母串）。
2) oneLiner：一句话解法，≤35 字，直接点破破题关键。
3) steps[]：三段式解题步骤，每项含 n（从1连续）、action（做什么，动词开头，≤12字）、
   why（为什么这么做，20~45字，不能只写结果）、detail（具体推理/公式，50~70字，边界放行±3字），
   两项下限都是强制的、要在区间内自然书写不要顶格凑字；锁定答案那一步标 "key": true，至多一个 key。图形推理题写 []。
4) errors[]：只列错项（正确项不写），o=选项字母，type 开放填写（按实际错因造词，越具体越好，
   如"中间量当答案"/"间距用错"，不受固定词表约束、只需非空）；why ≤30字。
   错项字母集合必须 = 所有选项字母 − 答案字母。
5) insight：对象，含 position（知识树坐标）、signal（识别信号）、essence（本质）、
   formula[]（可套通式）、pitfalls[]（易混易错）、strategy 子对象
   {shouldDo, bestWay, timeCost, traps}。禁止「本题考查XX，要注意XX」式空话。

输出 JSON 结构：
{
  "subject": "科目名（判断推理/常识应用/数量关系/言语理解/资料分析）",
  "node_name": "知识点节点名（须与画布现有节点一致，否则入库匹配失败）",
  "num": 题号, "src": "2025广东省考真题 第N题",
  "hit": false, "ans": "正确答案", "opts": [...],
  "q": "题干原文", "img": "assets/img/xxx.ext 或留空",
  "solution": { ...按上述五块... }
}

【题目】
题干：{{q}}
选项：{{opts}}
正确答案：{{ans}}
是否做错：{{hit}}
```

`questions.json` 样例（可直接作为 `ingest.py --file` 的输入）：

```json
[
  {
    "subject": "判断推理", "node_name": "逆否等价", "num": 53,
    "src": "2025广东省考真题 第53题", "hit": false, "ans": "A",
    "q": "……由此可以推出：",
    "opts": ["A. ……", "B. ……", "C. ……", "D. ……"],
    "img": "",
    "solution": {
      "answer": "A", "oneLiner": "翻成箭头串链后整体逆否，A 正是此式",
      "steps": [{"n":1,"action":"逐句翻译成箭头","why":"条件句不翻译无从推理","detail":"只有S才M⇒M→S","key":true}],
      "errors": [{"o":"B","type":"肯后推肯前","why":"题干 M→S，B 写成 S→M"}],
      "insight": {
        "position":"判断推理 → 逻辑判断 → 翻译推理 → 逆否等价",
        "signal":"出现「只有…才」「只要…就」→先全翻箭头","essence":"只有肯前推肯后、否后推否前有效",
        "formula":["只有A才B ⇒ B→A"], "pitfalls":["必要后推前、充分前推后别混"],
        "strategy":{"shouldDo":"必做","bestWay":"先全翻箭头再比对","timeCost":"约60秒","traps":"「关键在于」非条件词"}
      }
    }
  }
]
```

> 规范细则见 `/workspace/解析数据规范v2.md`，完整样板见 `/workspace/解析样板题v2.json`（用 `--samples` 校验）。

**产物**：`questions.json`（每题含完整 `solution` 五块结构）。

### Step 5　`validate_v2.py` 校验

```bash
# 校验批量输入（脚本递归找所有含 solution 的对象）

# 校验官方样板（走 samples 数组）

```

脚本实际检查项（读源码）：`answer` 与 `ans` 一致；`oneLiner` ≤35；`steps.n` 连续、`action`≤12/`why` 20~45/`detail` 50~70（下限也拦截，太短或太长都 FAIL；**边界放行 ±3 字**，即 why 17~48、detail 47~73、oneLiner≤38、error.why≤33 均通过）、至多一个 `key`；`errors` 字母集合 = 选项字母 − 答案字母；`error.type` **仅需非空**（开放填写、不查词表）、`why`≤30；`insight` 为对象且含 `strategy`（缺 `signal/essence/formula/pitfalls/strategy` 子字段会告警）。末尾打印错误类型分布，**有 FAIL 时退出码非 0**。

典型输出：

```
校验: questions.json
题目数: 31

[PASS] 2025广东省考真题 第6题  (三段式步骤3)
[FAIL] 2025广东省考真题 第9题
       ✗ errors 字母 ['B','C'] != 期望 ['B','C','D']
       ✗ steps[2].detail 超 80 字（86）
==================================================
结果: 30/31 通过, 1 失败
```

失败就回到 Step 4 修 `questions.json`，直到全 PASS 再入库。

### Step 6　挂到导图节点 + `ingest.py` 入库

**6.1 先确定节点 id**（脚本支持 `node_id` 直给，或 `subject`+`node_name` 精确/包含匹配；经验 7 明确「用真实 `--node-id`，不要猜 `--node-name`」）：

```bash
curl -s 'http://127.0.0.1:8800/api/nodes?subject=判断推理' \
  | python3 -c "import json,sys; [print(n['id'], n['name']) for n in json.load(sys.stdin) if '逆否' in n['name']]"
# 例：nx3f9a  逆否等价
```

**6.2 批量入库**（`questions.json` 数组）：

```bash
python3 tools/ingest.py --file questions.json
# 批量导入完成: 成功 31, 失败 0
```

单题快速入库：

```bash
python3 tools/ingest.py --subject 判断推理 --node-id nx3f9a \
  --q "题干" --src "2025广东省考真题 第53题" --ans A \
  --opts '["A. 甲","B. 乙"]' --solve "解法" --analysis "解析" --img "" --hit false
```

## 五、关键决策点

1. **新科目怎么处理**：`split_data.py` 的 `SUBJECT_FILE_MAP` 是硬编码五科，`verify_deploy.py` 的试卷下拉框断言写死「6 个 option」。新增科目需同步改：脚本映射表、前端 palette/order、验证断言，并重新核对首屏 manifest。本次试卷的「政治理论/科学推理」在现有五科体系里应就近归入「常识应用」，**不要新增科目**。

2. **题目挂到哪个节点**：优先 `node_id` 直给（用 `/api/nodes?subject=...` 查真实 id）；只有备选才用 `subject`+`node_name` 包含匹配。节点名必须与现有树一致，否则 `ingest` 返回「无 node_id 且无法按名称匹配」。找不到合适节点时应先补节点再挂题，不要硬塞到近似节点。

3. **配图存仓库 `assets/img/`（同域相对路径）**：`pdf_extract.py --imgdir` 只把图片落盘，不自动关联题号。流程是「人工确认图→题对应关系 → 图片复制到 `mindmap-demo/assets/img/` → `img` 字段填同域相对路径 `assets/img/xxx.ext`」。
   - **为什么不用 OSS**：2026.06 阿里云 OSS 欠费触发 `UserDisable`，线上 8 张配图全部 403 挂掉；而 GitHub Pages 仓库与网页同源、零费用、站点在图就在，已全量迁回（38 张）、彻底摆脱外链依赖。历史 OSS 脚本 `upload_b64_to_oss.py` / `upload_q71_material.py` 仅作留档，**不再使用**。
   - **命名规范**：用 OSS 相对路径或题号改写为安全文件名（如 `pd_1-15b1fb25c0.png`、`b64_b64_08_b57e5d53.jpg`），保证一张图一个文件、可被 Git 追踪。
   - **迁移/替换脚本**：`/tmp/do_migrate.py`（本地图→assets/img + 生成替换表）、`/tmp/replace_urls.py`（按替换表批量改四轨数据的 `img` 字段），替换后必须确认 `残留 aliyuncs = 0` 且 `assets/img` 引用文件全部存在。
   - **前端渲染**：`img` 有值即在题目卡片显示并支持 Lightbox 放大；v2 朱批解析在右栏，两者互不干扰。验证用 `verify_deploy.py` 的「真实加载 naturalWidth>0 + Lightbox 可放大」检查（去掉旧的 `page.route` 拦截图片逻辑，现在图片是本地同域、加载快）。

4. **批量 vs 单题**：31 道错题一律走 `--file questions.json` 批量（一次脚本调用、统一校验、统一注入）；单题 `--subject/--node-id/--q ...` 仅用于临时补录/验证链路。批量前务必先 `validate_v2.py` 全 PASS，避免带病入库后逐条返工。

5. **卷名字段**：数据里没有独立卷名字段，试卷信息只藏在 `src`（如 `2025广东省考真题 第53题`），前端用 `volOf(src)` 截「 第」之前作为卷名——所以 `src` 命名要规范统一，否则筛选下拉会出现多个近似卷名。

## 六、踩坑清单（源自实施经验文档）

1. **`ingest.py` 不带 `solution`**：API body 只有旧字段，v2 解析必须单独注入 `data.json` + `data/subjects/pN.json` + `data.js` 三处，否则画布看不到朱批五块（经验 4.7）。
2. **`--node-name` 靠猜必失败**：用 `/api/nodes?subject=...` 查真实 `--node-id`，包含匹配容易挂错节点（经验 7）。
3. **PDF 中文乱码 / 行内选项未拆**：乱码多为测试 PDF 字体嵌入问题，真实卷要实测；`A. 96 B. 100` 行内选项靠 `([A-D])\s*[.．、:：]\s*` 正则拆，提取器已内置但复杂排版仍要人工看 `raw`（经验 6.3）。
4. **答案标记不在提取块里**：本卷 90 题仅 23 题的 `raw` 同时含「正确答案/你的答案」，且 4 组答案对跨页/多选格式没被正则捕获——错题识别必须全文正则 + 人工核对，别信分块（本次实测）。
5. **多次上传 = 多次部署**：逐文件 `PUT /contents` 会让一次改动触发 N 次 workflow、产生 cancelled/failure；用 `gh_upload_atomic.py` 一次 commit 提交全部文件（经验 5.6）。
6. **`git push` 超时**：`github.com:443` 不通时改用 `api.github.com`（Contents API / Git Data API），凭证由 `gh` 管理（经验 5.2）。
7. **线上验证注意 JSHandle 类型**：`wait_for_function` 返回 `JSHandle` 须 `.json_value()` 转 Python 值，直接 `>` 比较会误报 FAIL（经验 5.7）。图片已改为仓库同域 `assets/img/`，无需再用 `page.route` 拦截 OSS 外链；验证时直接检查 `naturalWidth>0` 即可。
8. **灌注数据丢字段**：从富源向精简结构迁移必须做字段清单对比，否则 `steps`/`exclude`/`solution` 会被静默丢弃，且示例数据阶段看不出来（经验 6.6）。
9. **样板只在 demo、权威源没有（本次实测）**：5 道 v2 样板此前只注入了 `mindmap-demo/data.json` 及分科文件，`mindmap-server/data.json` 里 `solution` 数为 0。此时若直接往源里注入新题再跑 `split_data.py`，会把 p1 的样板**整批冲掉**（本次 p1 一度从 164623B 掉到 153503B 才发现）。做法：先以 demo 的完整对象为基准把新题并进去，再**同时覆盖** `server/data.json` + `demo/data.json` + `demo/data.js` 三处，最后才 split；split 后核对 p1 体积/样板数是否恢复。
10. **`validate_v2.py` 曾把每道带 solution 的题数两遍**：旧 `iter_examples()` 对同时出现在 `examples[]` 里、自身又含 `solution` 的对象会 yield 两次，导致「题目数: 2」实为 1 道、报告虚高。已改为按对象 `id` 去重（本次修复）。
11. **资料分析材料：仓库截图为主，文字内嵌为可选兜底**：资料分析题的材料是数据表格，`pdf_extract.py --imgdir` 只把表格图落盘、不带数据层。第71题先做了文字内嵌兜底，后按用户要求**只留截图**——把表格关键数据从题干 `q` 删掉，仅保留问题句，`img` 填仓库相对路径 `assets/img/xxx.png`（直观、可放大、零费用）。**教训**：曾填 OSS 外链，欠费后全部挂掉；现在一律存仓库、不依赖任何外部图床/对象存储。若截图确实拿不到，退回文字内嵌也能正常工作。
12. **`hit`（做对/做错标签）别手填，要从答案对派生（本次实测）**：第71题录入时把 `hit` 手滑写成 `true`，但 PDF 里正确答案 A、你的答案 B，明明是**错题**——线上就显示成「✅ 做对」，与 PDF 对不上。`hit` 的语义是 `true=做对 / false=做错`，**唯一正确来源是 `set(正确答案) == set(你的答案)`**，绝不能凭印象写。修正方法：全文正则解析 PDF 的 90 组答案对（本卷解析出 30 道错题），与导图所有 `2025广东省考真题 第N题` 的 `hit` 逐一对照，只改冲突项（本次仅第71题 1 处冲突，其余 41 道均一致）。前端左栏 `.ex-tag` 和右栏朱批 `.zp-tag-*` 都由 `hit` 自动渲染，改数据即可、无需动前端。批量录入应写进脚本自动派生 `hit`，杜绝手填。

## 附二：资料分析归类判定规范（2026-11-19 补录 7 题挂错节点后的固化）

> **病根**：补录 2025 广东省考 7 题时，74/84/89 三题被硬塞进「其他综合 > 综合 > 能够推出判断」。
> 原因不是解析写错——三题 `insight.position` 本就标对了知识点——而是入库时图省事，把所有新题都挂到同一个兜底节点。
> **「能够推出判断」是综合题的专属节点，不是收纳未知考点的垃圾桶。**

### 1. 归类三问法（挂节点前必答）

1. **题干问的是什么量？** 增量 / 增速 / 比重 / 平均数 / 综合判断？—— 看问法，不看材料讲什么主题。
2. **用什么公式做？** 对照知识树节点名里的公式，选公式一致的节点。
3. **解析 `insight.position` 标的什么坐标？** 写解析时已做过一次归类，挂载节点应与它对齐；两者不一致，十有八九是挂错了。

### 2. 问法 → 节点速查表

| 题干典型问法 | 核心考点 | 正确归类 |
|---|---|---|
| 同比**增加数量**最多 / 同比增量 / 增长量是多少 | 增长量 | 增长 > 增长量 > 增长量：Δ=现期−基期=基期×r=现期×r/(1+r) |
| 同比**增长率**最高/最低的是 | 增长率比大小 | 增长 > 增长率 > 增长率（主式） |
| 求「1~N 月」而材料只给累计与单月 | 累计求当期 | 增长 > 其他 > 累计求当期 |
| 平均运送距离 / 平均单价 / 平均量最短最高 | 现期平均数（比值） | 平均数与倍数 > 平均数 > 现期平均数 |
| 占比 / 比重是多少 | 现期比重 | 比重 > 现期比重 |
| 占比上升下降多少个百分点 | 两期比重差 | 比重 > 两期比重差 |
| **以下说法正确/有误/不正确的是**（四项各考不同点，须逐项验） | 综合判断 | 其他综合 > 综合 > 能够推出判断 |

**判分水岭**：只有「四个选项涉及不同考点、必须逐项验证」的题才进「能够推出判断」；
凡是题干锁定单一考点（求增量、求增速、求比重、求均值）的题，一律归到对应知识点节点。

## 附三：题目索引工具（AI 审查省上下文，2026-11-19 定稿）

> **用途**：AI 核对/审查某题时，不必把整份分科文件（p5 约 4 万 token）读进上下文。
> 先读轻量索引（全库 6764 token）定位，再按题抽单题全文（约 400 token）。随审查题数线性增长，而非每次全量。
> **仅为 AI 审查派生工具**：只读源数据、默认输出 `/tmp`、不落仓库、前端不用、不改任何数据文件。

```bash
cd /workspace/mindmap-server
# ① 生成精简索引（题号/卷名/答案/知识点末级/是否有图，全库约 6764 token）
python3 tools/question_index.py build                       # → /tmp/question_index.json
python3 tools/question_index.py build --subject 资料分析     # 只要某一科
python3 tools/question_index.py build --full                # 追加一句话解法+position（约1.4万token）

# ② 按需抽单题全文（三种定位；题号撞车时用「卷名+题号」）
python3 tools/question_index.py get 84 --vol 2025广东省考真题       # 推荐：卷名+题号精确
python3 tools/question_index.py get "2025广东省考真题 第84题"        # 完整 src 精确
python3 tools/question_index.py get 84 --subject 资料分析 --all      # 列出全部同号题
python3 tools/question_index.py get 84 --vol 26年省考35季 --fields oneLiner,steps,errors  # 只取解析某几块
```

> **为何加卷名**：`get 84` 会命中 2025/26省考35季/2026 三道第84题（项目老坑——题号跨卷撞车），必须用 `--vol` 或完整 src 区分。索引的 `vol` 字段就是为此。
