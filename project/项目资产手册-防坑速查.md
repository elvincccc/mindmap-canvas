## 〇、先定性：这个项目到底沉淀了什么

按我的模型推——一个项目值不值得沉淀，看它留下的是"一次性成果"还是"可迁移资产"。本次留下三笔真资产：

| 资产 | 内容 | 迁移价值 |
|---|---|---|
| **架构资产** | 数据与视图分离 + 任意深度递归 + 不可变基线 + 三轨数据兜底 | 任何"树形可视化 + 内容管理"项目直接搬 |

**一句话心法**（先把结论甩这儿）：

> **先存基线再动刀，数据视图两分开；派生字段不手写，因题择法不泛化；原子提交一次过，禁缓存才验真。**

## 三、防坑速查表（按场景查）

口诀都是compressed版，出处见括号。遇到症状直接对号入座。

### A. 架构 / 解耦

| 症状 | 根因 | 对策 | 口诀（出处） |
|---|---|---|---|
| 换数据要改引擎 | 数据与视图耦合 | data.json / data.js / API 三轨分离，buildTree 只读数据 | 换数据不换引擎（阶段1，20KB minimal 实验） |
| 层级只支持 L3 | 递归深度写死 | 改成任意深度递归 | 递归不限深（3.3） |
| 改造没底线 | 无基线 | baseline 存档 + 校验 | 先存基线再动刀（方法论1） |
| 灌注真实数据后 steps/exclude 丢了 | 只灌主字段 | 从 baseline 找回步骤与排除项 | 灌注别丢元数据（6.6） |

### B. 数据处理

| 症状 | 根因 | 对策 | 口诀（出处） |
|---|---|---|---|
| ans/hit 写错 | 手写 | PDF 答案表 zip 派生，写也覆盖 | 派生不手写（零章 / 第71题） |
| data.js 兜底不生效 | 格式不是 `window.MM_DATA={...}` | 自动识别格式写回 | 兜底格式要认（batch_inject 改造） |
| 改了不生效 | 多副本不一致 | 确立单一权威 data.json | 数据源要单一（8.2） |
| URL 编码 SVG 上传失败 | 当 base64 处理 | 用 `unquote_to_bytes` 解码 | SVG 先解码再传（tools/README） |
| 下拉中文被截断 | `max-width` 写死 | `canvas.measureText` 按最长选项量宽 | 用户文本别写死宽（后端前端表） |
| 线上配图全挂 | 图片放第三方 OSS，欠费 `UserDisable` | 图片存仓库 `assets/img/`，用同域相对路径 | 图存自家仓库，不欠费不跑路（6.18） |
| 图配错题 | 多试卷同题号，按题号硬配 | 按题干内容核对，题号只作线索 | 题号会撞车，配图认题干（6.18） |

### C. 解析内容

| 症状 | 根因 | 对策 | 口诀（出处） |
|---|---|---|---|
| 解析五块乱写 | 无结构 | 固定 answer/oneLiner/steps/errors/insight | 五块固定、字数校验（规范v2） |
| 代入法泛化翻车 | 一招当万能 | 先定性再选法，按结构匹配 | 因题择法不泛化（6.14，用户纠正） |
| 错因写一大堆 | errors 写成全部选项 | 只写错项 | 错因只写错项（规范v2） |
| 符号有歧义 | "甲乙=100"像人名 | 写全运算符"甲＋乙＝100" | 符号说人话（6.14） |
| 配图题盲写错 | 凭旧解析 | 逐张下载原图读图再写 | 图不读不写（6.9 / 6.14） |
| 比重变化硬算两期占比 | 分别除增长率再相除，慢且易飘 | 增速差 a−b 定向、现期占比×(a−b)估幅度 | 比重变化看增速差，别硬算（第77题，用户纠正） |
| 单价/比值逐项全除 | 四个选项各算一次除法，掉进时间黑洞 | 扫分母找断崖最小项→心算它→只对最强对手交叉相乘 | 单价比较盯分母，断崖项秒算（第87题） |
| 首超逐年累加 | 增量不变硬逐年加，慢且易多加一年 | n=(目标−现期)/增量 向上取整→回代验临界 | 首超算商进一取，回代验临界（第83、78题） |
| 解析整段串题 | 批量重写时相邻题解析串行，内容与题干无关 | 审稿必查"解析关键字与题匹配"，串题检测 | 写完回头对题干，串题比算错更隐蔽（6.18，2024广东30） |
| 步骤与结论矛盾 | 某步判X错、结论却判X对 | 逐项落定后再计数，交叉核对步骤与答案 | 步骤结论要一致，自相矛盾必回炉（6.18，2026广东66） |
| 加权平均乱定位 | 用"必有高低"推出某具体地区高/低 | 加权平均只断定"存在"，定位具体项要用材料直接数据 | 平均只证存在，不证是谁（6.18，2024广东90） |
| 批量写一半崩 | 一上来铺开全部 | 样稿定标尺 + 分批校验 + 闭环验收 | 先立标尺再放大（6.9） |

| **直接搬** | 不可变基线、三轨数据兜底、任意深度递归、v2 五块 + 校验、原子部署、四重禁缓存验证、分科按需加载 | 与领域无关，验证过的通用件 |
| **要改造** | batch_inject 的科目映射、筛选器宽度函数、朱批配色、牌面字号档位 | 绑定了本项目数据/视觉，换项目要重配 |
| **别搬** | 具体口诀话术、行测题库内容、一次性脚本（fix_q71 等） | 场景专属，无迁移价值 |

> 边界：方法针对行测这个项目高度优化，迁移到其他领域请先验证适配，别把经验当教条——同第6.14条的"因题择法"一个道理。

---

## 六、复盘框架（按我的模型推）

用解题的那套思维工具回看整个项目，四步闭环：

1. **定性先行**：先答"这是什么项目"——树形可视化 + 内容工程 + 静态发布，三件事叠在一起，所以坑分三类来治。
2. **找主要矛盾**：真正的杠杆是"数据与视图分离"（3.1），其余 UI、部署都是在这个地基上盖的。地基对了，后面都顺。
3. **出题人视角找坑**：把每次翻车当"出题人挖的坑"——手写答案、写死宽度、缓存假阳性，都是看似没问题、实则必踩的陷阱。提前列铁律，就是提前识坑。
4. **复盘成资产**：踩过的坑不写下来就是白踩。固化为脚本 + 校验 + 这份手册，下次同类项目直接调用，这才叫复利。
